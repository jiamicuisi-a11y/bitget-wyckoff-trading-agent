# Agent OS Track A · 2–3 分钟 Demo 脚本

## 0:00–0:15 · 先讲清楚产品

“这是 Strategy Copilot。它把我原来 Bitget 项目里最稳定的两套 Paper 策略——A 档异动扫描和 4H 双均线——放进一个 Agent OS 工作流；同时把 Binance 官方活动、公告和行业资讯纳入市场情报层。Agent 会感知 Binance 永续市场，把候选变成可点击的研究卡片，展示 K 线和交易计划，经过 Risk Gate 后再写入本地模拟账本。”

指向左下角：`PAPER MODE`。补一句：

“今天展示的是公开行情、公开资讯和本地模拟账本，不连接账户，也不会发送真实订单。”

## 0:15–0:35 · 展示市场情报与官方活动

点击侧边栏的 `市场情报`，先选择 `Binance 活动`，再输入 `BTC` 并点击 `筛选`。

解释：

“这里把 Binance 官方活动、官方公告和 CoinDesk 行业资讯分开呈现。每条都有时间、来源、原文入口，BTC 这样的关联资产还会显示当前公开行情。右侧是官方活动规则入口，但页面不会判断资格或替用户报名。”

点击一条 `查看原文`，停留在页面内说明即可，不必打开外部站点。然后点击刷新图标，展示数据同步状态。

补一句：

“这些是公开 CMS 和 RSS 的只读信息源，不把它们伪装成 Binance MCP 的账户授权。”

## 0:35–0:58 · 展示两套策略

依次点击：

1. `A档 · 异动扫描（Binance）`
2. `双均线 · Binance 4H`

解释：

“A 档把 OI、价格、成交额、盘口和资金费率合成一个机会分数；双均线只看成交额 Top30 的 4H EMA(10/30) 金叉或死叉。两套策略共享同一条 Agent 工作流，但各自保持独立参数和 Paper 账本。”

## 0:58–1:38 · 用 Agent 完成一条闭环

进入 `Agent 对话`，先输入：`Binance 最近有哪些活动可以参与？`，展示 `binance_activity_list` Tool Trace 与原始规则链接；再输入：`扫描全市场，告诉我现在最值得研究的机会`。演示以下动作：

1. Agent 返回覆盖数量和候选卡片。
2. 点击一张候选卡，展示 K 线上的计划入场、止损、止盈。
3. 点击「生成 Paper 计划」，展示策略评分、风险边界和审计 ID。
4. 点击「确认加入 Paper」，只写入本地 SQLite 模拟账本。
5. 打开 `运行记录`，展示候选确认 → 风险闸门 → Paper 执行 → 审计记录。

后台策略 worker 仍然持续自动扫描和管理两套策略的模拟仓，不需要手动“运行一次”或“刷新扫描”。

策略页会显示完整扫描覆盖、候选分数、Paper 持仓、权益曲线和交易检查器。点击候选或 Paper 记录，可以解释「为什么选它」以及入场/止损/止盈相对 K 线的位置。`/api/agent/run` 生成不可广播的 Paper plan，`/api/agent/confirm` 才会在用户明确点击后写入本地模拟账本。

## 1:38–2:10 · 解释 Risk Gate

指向风险闸门：

“关键点是 Agent 不会直接从行情跳到下单。它必须先经过风控，并且人工确认仍然是最后一道门。当前权限只有 `Market data · Paper execution`，明确没有提现权限。”

## 2:10–2:30 · 收尾

“所以这个 Agent 的价值不是一个黑盒信号，而是一条可解释、可审计、默认安全的策略执行链。把原来分散的策略研究和模拟盘，变成一个可以被自然语言驱动的 Binance Agent OS 控制面。”

## 录制前检查

- 启动：`node scripts/local-service.mjs start`
- 页面：`http://localhost:4180`
- 确认左下角显示 `PAPER MODE`
- 确认顶部显示 `Binance Futures`
- 确认至少有一轮后台扫描完成；A 档首轮可能只建立 OI 基线，下一轮才出现 OI 变化分
- 录屏中不要展示任何 API key、Cookie、钱包或真实订单页面
